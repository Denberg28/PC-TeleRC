# Restrained commissioning and acceptance

Use the complete 0.2.0rc1 generated BASE/ROVER/NODE set and PC 0.1.5rc2.
Verify the TM2 route/mask handshake, relative stopped action windows and actual
ON/OFF timing. Native USB must be hardware CDC/JTAG with CDC on boot enabled.

Run in order and record PASS / FAIL / BLOCKED, firmware hashes, FC firmware/parameter backup, board revisions, antennas, batteries, RF route and observed timing. Software checks cannot establish physical stop timing or antenna performance.

1. **Motors disconnected.** Generate one direct pair. Compile the actual SX1262 BASE and ROVER, flash matching profiles, verify RF initializes. Confirm an unprovisioned public example leaves RF OFF. Verify the OLED sleeps at 30 seconds and BOOT only wakes it; no communication/mode/arming event may follow display actions.
2. **FC identity and arming.** With motor power still disconnected, wire UART43/44 cross-connected to FC RX/TX, set matching rover/FC IDs and serial baud/protocol. Run gateway and client. Confirm heartbeat is genuine ArduRover sys-ID/comp1. A second FC/rover ID must not appear as the selected rover. Confirm the original RC handset can still select MANUAL/HOLD and arm/disarm with all appropriate FC checks.
3. **No automatic motion authority.** Start/reset BASE, ROVER and relays individually; unplug/replug USB; kill/restart the gateway/client. None may arm, start AUTO, generate RC override or re-send a prior START. FC failsafe and handset state remain authoritative. A base connection LED alone must never be logged as FC connectivity.
4. **Security.** Flash a second test ROVER with a separately generated key; it must not accept commands from the first set even with identical IDs/frequency. Try the same fleet with different fleet ID and relay count. Expect no accepted mission/start; never disable authentication to repair a mismatch. Restore the complete matching set afterward.
5. **Disarmed upload/readback.** In MANUAL/HOLD upload a short reviewed route with motor power absent. Confirm accepted upload and full actionable readback. Compare against Mission Planner connected directly afterward. Interrupt RF/USB during different upload steps; the client must never offer successful verification for incomplete data. Reconnect must require a new deliberate upload/verification. Do not assume an interrupted FC mission stayed unchanged.
6. **Manual arming and one START.** Use the `--start` flow with motors still disconnected. Verify no START before full readback and typed target/digest confirmation. Arm through the handset in MANUAL/HOLD. Confirm only one START, accepted command ACK plus real ARMED AUTO heartbeat. A missing ACK must display UNKNOWN and must not trigger an automatic second START. Confirm HOLD through the handset and the tool. Check auxiliary functions independently; no automatic servo-safe-state claim is made.
7. **Rover separation.** Repeat with IDs 1 and 2 and distinct SYSID_THISMAV values. Upload different plans while only the addressed FC is connected/selected. Inspect both stored plans directly. Attempt mismatched inner/outer targets through test tooling: no plan mutation or START on either unintended rover. Observe the 5-second quiet interval when changing BASE's selected session.
8. **One and two relays.** Re-provision all boards with the same relay count. Position NODE_1 nearest BASE, NODE_2 nearest ROVER. Repeat upload, readback, START and HOLD. Test overlap where BASE and ROVER also hear some direct RF, then test loss of each relay. Wrong-stage/direct overhearing must not suppress the valid relayed copy. Remove one relay during upload: bounded timeout, no automatic start or route discovery flood. Measure transaction time and delivery loss with real antennas.
9. **Raised wheels at low speed.** Secure the rover, keep clear of wheels, and have an independent physical stop. Restore motor power only after the above checks pass. Use low WP_SPEED and the validated dedicated motor converter. Measure supply voltage during steer/drive combinations; resolve resets/brownouts before blaming or weakening watchdogs. Verify RC takeover, HOLD and stopping distance. Do not bypass arming/navigation checks to get this test moving.
10. **Real link-loss policy.** Default profile FS_GCS_ENABLE=1 / FS_ACTION=2: after the client has actually sent GCS heartbeats, remove RF/USB and time the FC entering HOLD and the physical motors stopping. Reconnect must not resume AUTO. Repeat RC loss, battery/fence/EKF protections appropriate to the build. HOLD delivery over a broken radio is impossible; verify independent takeover/stop.
11. **Optional continuation profile.** Only after restrained tests pass, explicitly configure FS_GCS_ENABLE=2 / FS_ACTION=2 and use `--continue-on-loss`. In a contained outdoor area, confirm an already running **onboard AUTO** mission continues when GCS heartbeats cease, and that other independent FC failsafes still act. Do not infer this from phone Guided waypoint behavior. Verify mission completion and auxiliary OFF/end-state actions. Document who may authorize this loss policy.
12. **Contained field test.** Begin with one rover, direct link, very short clear route, low speed, verified GPS/compass/EKF/fence, working RC and physical stop. Increase range, add one relay, then add another rover separately. Record measured loss, mission transfer time, remote HOLD latency, FC loss-to-HOLD time and actual stopping distance. Twenty unique IDs are an addressing capacity, not evidence of twenty simultaneous reliable radio sessions.

Stop qualification on unexpected mode changes, stale telemetry presented as fresh, wrong-rover messages, uncontrolled auxiliary outputs, brownouts, UART conflicts, failed takeover or a mismatch between displayed and FC mission state. Restore the working manual firmware and saved FC parameters with power removed before further driving.
