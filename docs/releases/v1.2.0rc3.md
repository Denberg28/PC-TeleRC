# PC TeleRC v1.2.0rc3 — map drag and coordinate correction

Fixes a geographic conversion error that shifted longitude by 180 degrees on
each drag update, making the map jump between opposite hemispheres. Waypoint
clicks used the same incorrect conversion. Both now use one tested inverse of
the map's world-pixel projection, with correct dateline wrapping.

**Review routes created with earlier builds before uploading or starting them.**
Map clicks in those builds could have saved incorrect longitudes. Existing
drafts and WPL files are preserved for review; coordinates are not automatically
rewritten because legitimate routes may be in either hemisphere.

Dragging now uses the total pointer displacement from a fixed starting view,
ignores small click jitter and processes the release position even when the
last mouse-move event was coalesced. Panning and manual zoom disable automatic
following/fitting until the operator explicitly chooses Follow or Fit fleet.
An interrupted gesture or lost mouse-button state cannot place a waypoint or
leave the map dragging. Horizontal-only wheel input does not change zoom.

Tests exercise real mouse-event sequences, geographic round trips, clicks in
both hemispheres, dateline crossings, release-only and interrupted drags,
fresh telemetry during manual browsing, and rendered terrain continuity.
The frozen Windows executable must pass equivalent drag/click checks before
publication, along with the existing fleet, layout and archive safety gates.

This is an application-only release candidate. Fleet firmware 0.5.0rc1, the
PWM converter 1.0.5, existing keys and saved routes retain their current formats.
No firmware reflash is needed for an existing matching fleet. Public LoRa
examples remain RF OFF. Independent FC checks and unknown/no-retry command
behavior remain unchanged. Physical RF, motor, FC and takeover qualification
remain pending; the app is unsigned.
