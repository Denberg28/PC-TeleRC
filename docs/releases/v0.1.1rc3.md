# PC TeleRC 0.1.1rc3 — input freshness and fail-safe reporting

The observed v0.1.0a10 screenshot shows a connected MAVLink session, a heartbeat
0.5 seconds old and PC control latched off. It does not show a current Wi-Fi
disconnect. The screenshot does not identify the earlier event that caused the
latch. It also shows stale command output and the old “PC control enabled” text.

Review found that wheel snapshots were handed to the control worker by the GUI
refresh timer. A blocked UI could therefore make the worker see stale input
while the independent wheel reader kept running. It also found that recovered
Wi-Fi heartbeats cleared the error text, hiding the stop reason.

The MAVLink worker now reads the wheel service's thread-safe snapshot directly
at each control tick. Enable and ARM checks also use a current snapshot. The
original acquisition timestamp is preserved, so missing or frozen wheel input
still stops control. SDL polling remains in the wheel thread; this change does
not add polling to the UI or perform hardware I/O in the snapshot supplier.

Heartbeat timeout now records its measured age and configured limit, displays
neutral command values, and preserves the reason after telemetry recovers.
Controller-loss and send-failure messages also survive recovered heartbeats.
The global status displays “Control stopped” while latched. Only an explicit,
successful re-enable clears the error. Neither timeouts nor manual-reenable
requirements are relaxed; the app never automatically resumes motion.

This patch is based on the available 0.1.1rc2 source, which carries the Wi-Fi,
LoRa and ELRS profiles. The screenshot shows the older 0.1.0a10 executable.
Updating only an ESP32 sketch cannot apply these PC-app fixes. The original
cause on the user's hardware remains unconfirmed until diagnostics/logs show
the event; this patch removes a demonstrable failure path and makes recurrence
diagnosable.

## Using the portable candidate

Close the old application, extract the entire portable ZIP into a new folder,
then open PC-TeleRC.exe. Confirm version 0.1.1rc3 in the title bar. Keep the app
and runtime folders beside the executable. The bundle reuses the existing rc2
Windows x64 launcher/runtime with the corrected application source.

For the shown setup, choose ESP32-S3 Wi-Fi, target 192.168.4.1, UDP 14550, CH1
steer and CH2 throttle. Keep the latest bridge sketch already provided. With
the rover secured for bench testing, center the wheel and release both pedals,
then use Re-enable PC Control. Apply & Reconnect is for an actual link/session
problem or connection-setting change, not the normal response to a recovered
fail-safe latch.

If a stop repeats, keep the displayed reason and copy Diagnostics before
re-enabling. Check whether it names stale controller input, missing heartbeat,
or a transmission failure. Changing all timeout values would conceal this
distinction rather than establish the cause.

Validation includes a no-GUI-refresh control simulation, genuine stale input,
controller removal, source failure, mapping validation, heartbeat loss and
recovery, and the existing suite. Native Windows launch and physical PXN/Wi-Fi/
ELRS testing remain unperformed. This is an unsigned test candidate; a10 remains
the stable reference. The firmware and responsive motor ramp are unchanged.
