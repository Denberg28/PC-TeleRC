# PC TeleRC v0.1.0a6 — First Windows Test Release

This is the first packaged Windows prerelease for controlled bench and field-module validation.

## Included
- Windows x64 portable executable
- PXN / compatible wheel input through pygame-ce
- Guided wheel and pedal calibration
- Steering expo and independent 25–100% steering sensitivity/gain
- MAVLink UDP bridge for ESP32-S3 / ArduRover
- Explicit ARM / DISARM and PC Control
- Controller and heartbeat watchdogs
- Vehicle system + component identity lock
- Repeated neutral / RC-override release on shutdown and fail-safe
- Minimal modeless Diagnostics: Link, Controller, Mapping, Safety
- Copyable diagnostic report and rotating local field log
- Persistent local settings

## Install
1. Extract the ZIP to a normal Windows folder.
2. Run `PC-TeleRC.exe`.
3. If Windows SmartScreen warns about the unsigned test build, verify the SHA-256 in `SHA256.txt` before proceeding.
4. Connect the PC to the ESP32-S3 rover network.
5. Select and calibrate the intended PXN/controller.
6. Resolve any Diagnostics FAIL state before enabling PC Control.

No installer, administrator permission, cloud account, database, API key, or signing key is required.

## First bench run
Keep the rover drive wheels physically clear of the ground.
- Confirm the correct controller is selected.
- Calibrate steering and pedals.
- Verify displayed steering/drive direction.
- Confirm the correct MAVLink vehicle system/component.
- Confirm steering/throttle RC channels.
- Start with the default 25% throttle limit.
- Test controller unplug, Wi-Fi loss, ESP32 power loss, app close, and FC reboot before ground operation.

ArduRover's independent GCS/telemetry fail-safe remains mandatory. PC TeleRC cannot guarantee a final MAVLink neutral packet after the network is already gone.

## Upgrade
This is the first packaged release. Future upgrades should replace the executable while retaining:
`%LOCALAPPDATA%\PC-TeleRC\settings.json`

Review the changelog before upgrading because control behavior and defaults may change during alpha development.

## Rollback
Keep the previous release ZIP/executable before replacing it. To roll back:
1. Disable/disarm the rover.
2. Close PC TeleRC.
3. Replace the executable with the previous verified version.
4. Re-open and re-run Diagnostics plus calibration verification before use.

If a future version changes the settings schema unexpectedly, rename or remove:
`%LOCALAPPDATA%\PC-TeleRC\settings.json`
and reconfigure from defaults.

## Known limitations
- Unsigned Windows executable.
- Hardware validation is still required for the actual PXN model/driver mode, ESP32-S3 bridge, ArduRover configuration, BTS7960 chain, and real Wi-Fi/controller fault timings.
- No force feedback.
- No mission planner/map functionality.
- No automatic update mechanism.
- Public field-ready status is not claimed yet.
