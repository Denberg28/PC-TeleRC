# PC TeleRC v0.1.0a8 — Persistent Single-Socket MAVLink

This maintenance prerelease replaces the previous UDP lifecycle design after bench diagnosis confirmed that Windows itself could bind UDP 14550 normally while PC TeleRC still experienced transient bind conflicts.

## Main fix
- Uses one persistent bound UDP socket for both MAVLink receive and transmit.
- ESP32 target IP/port changes update the existing socket in place.
- UDP listener restarts only when the listen address or listen port changes.
- Duplicate start requests are idempotent.
- Send operations and live target updates are serialized.
- Listener lifecycle regression tests are included.

## Windows packaging
- Switched from PyInstaller one-file to **onedir** inside the Inno Setup installer.
- Installed PC TeleRC now runs as one normal application process instead of the one-file bootloader/child process pair.
- Portable distribution is now a ZIP containing the full application folder.

## Why this release exists
Bench troubleshooting confirmed:
- UDP 14550 was not held by Mission Planner or another persistent process.
- UDP 14550 was not in Windows excluded UDP ranges.
- Windows `UdpClient(14550)` bind succeeded repeatedly.

That evidence points to the previous PC TeleRC socket lifecycle as the remaining cause of the transient WinError 10048 behavior.

## Existing safety behavior retained
- Explicit ARM / DISARM.
- PC Control requires healthy MAVLink, fresh controller input and neutral throttle.
- Controller/MAVLink loss latches PC Control OFF.
- Strict selected-controller GUID.
- Vehicle system + component identity lock.
- Multi-attempt neutral/release sequence.
- ArduRover GCS/telemetry fail-safe remains mandatory.

## Installation
Use **PC-TeleRC-Setup-v0.1.0a8.exe** for normal installation. Existing settings under `%LOCALAPPDATA%\PC-TeleRC` are preserved.

## Bench validation
1. Close Mission Planner and other MAVLink listeners.
2. Install v0.1.0a8.
3. Start PC TeleRC and confirm only one application process is visible.
4. Confirm Diagnostics Link has no FAIL state.
5. Connect ESP32-S3 Wi-Fi and verify heartbeat/RX traffic.
6. Change only ESP32 target IP/port and confirm the listener does not rebind.
7. Test controller unplug and Wi-Fi loss with wheels clear of the ground.

This remains a prerelease until the complete physical fail-safe matrix is recorded.
