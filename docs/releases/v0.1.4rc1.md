# PC TeleRC v0.1.4rc1 — TeleRC workflow and cockpit migration

App-only Windows release candidate based on desktop v0.1.3 (`0edd09475dd4668a8793caf1402b15d3f35d0a1b`) and TeleRC 0.8.81 (`38b2310342f510b344ee4e6413e142a8f6533424`). The owner requested feature migration, connection/telemetry improvements, a DJI-style UI and a release build on 18 October 2026.

## Changes

- Camera-first cockpit with dedicated ground speed, battery, GPS fix and heartbeat-age tiles. Stale arm/mode values are identified as last-known values. No fabricated link-quality percentage.
- Lower-left rover map with 160 ms map/camera swap, minimize-to-chip and restore. The same map/camera instances stay alive; preferences persist. Offline raster MBTiles and the v0.1.3 tile cache remain supported.
- Connect/reconnect/disconnect available directly above the camera; detailed connection/input/camera settings remain in the side drawer.
- Selected-source camera reconnection after loss/stall: retries back off from 1 to 8 seconds, one active attempt at a time. Stop cancels retries; USB identity never falls back to another camera. Camera URLs retain the existing credential/token removal on save.
- New **ELRS Backpack · handset control** Wi-Fi telemetry profile. Defaults: Backpack `10.0.0.1:14555`, PC listen `14550`. Settings are independent of the original Wi-Fi and USB profiles.
- Registration PING retries continue once per second through stale telemetry. Native Backpack output is guarded at both service and transport layers: no GCS heartbeat, drive, ARM/DISARM, neutral/release or bridge commands. Handset remains the authority.
- GPS position refresh now requires a recent valid fix; GLOBAL_POSITION_INT cannot reuse an expired fix. Worker checks old heartbeat age before accepting a recovered heartbeat, including a slow receive iteration.

## Connection workflow

| Profile | Operator workflow | Authority |
| --- | --- | --- |
| ESP32-S3 / LilyGO Wi-Fi | Join rover Wi-Fi → Connect → fresh heartbeat → neutral input → Enable PC Control → explicit ARM | Existing TeleRC bridge contract |
| LilyGO LoRa USB | Connect native BASE USB → choose COM → Connect → fresh rover/remote status → neutral acquisition → explicit ARM | Existing MANUAL/DIRECT contract |
| ELRS USB PC control | Select compatible TX USB MAVLink port → Connect → fresh ArduRover heartbeat → neutral → manual enable/ARM | Existing experimental USB path; handset arbitration requires HIL |
| ELRS Backpack handset control | Enable ELRS MAVLink and Backpack Telemetry WiFi → join telemetry AP/router → set actual peer → Connect | Handset drives and arms; PC shows telemetry/FPV |

Backpack firmware-update Wi-Fi is a separate service. Defaults match the [ExpressLRS MAVLink documentation](https://www.expresslrs.org/software/mavlink/). PC registration is not a GCS heartbeat and must not be counted as FC GCS failsafe supervision. Retain an independently verified RF-loss HOLD action. Automatic registration uses the same configured peer; DHCP peer changes need an explicit address edit and reconnect. Explicit Disconnect stops the worker and registration. No automatic serial reopen/COM scan is added.

For supported handset/PC handover, retain ELRS CRSF into the F405 plus the separate existing FC Wi-Fi/LoRa link and the FC override-enable switch. Native Backpack mission upload, Guided commands and live Waypoint are not added. The desktop map remains read-only. Test/game/marketplace features are outside this operator release.

## Installation and rollback

Use `PC-TeleRC-Setup-v0.1.4rc1.exe`, or extract the portable ZIP and run `PC-TeleRC.exe`. Close the earlier instance first; only one app may own UDP 14550 or a radio COM port. Back up `%LOCALAPPDATA%\PC-TeleRC\settings.json` before upgrade. Existing wheel calibration, radio ports and CH1 steer/CH2 drive defaults are retained. The installer AppId and destination are unchanged. No board firmware or FC parameter changes are bundled or required. Keep [v0.1.3](https://github.com/Denberg28/PC-TeleRC/releases/tag/v0.1.3) for rollback and its exact LoRa preset/targets. Restore the settings backup if rolling back.

## Evidence and limitations

Software regression, real localhost UDP/MAVLink and HTTP video, UI layout/swap and frozen Windows media/package checks are required by the candidate workflow. `build-provenance.json`, `frozen-ui-check.json` and SHA256 manifest tie binaries to the tested commit/run. Draft assets are uploaded only after those checks pass. Actual Windows installation, PXN input, USB FPV hotplug, Wi-Fi changes, ELRS RF loss and rover output timing remain NOT TESTED; candidate status is retained. The executable is unsigned.

4. Drop telemetry beyond the configured heartbeat timeout; registration must continue, stale GPS/battery/arm state must not appear current. Restore telemetry; no drive/ARM output may occur. Explicit Disconnect must cancel registration. Change Backpack IP explicitly if DHCP assigns another peer.
5. Swap/minimize/restore repeatedly, resize with Settings open and closed, and open offline MBTiles. Camera must remain the same stream. Disconnect/reconnect the selected FPV receiver ten times; verify retry/Stop, identity retention and the absence of control side effects.
6. With phone/PC absent, independently test ELRS RF-loss HOLD and recovery. Record actual motor behavior and deliberate handset recovery. Successful telemetry recovery does not prove RF failsafe behavior.
