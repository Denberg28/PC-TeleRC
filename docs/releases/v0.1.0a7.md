# PC TeleRC v0.1.0a7 — Windows UDP Reliability

Maintenance prerelease based on real Windows bench testing with PXN-V3II and the ESP32-S3 MAVLink workflow.

## Fixes
- Prevents a second PC TeleRC instance from launching and competing for UDP 14550.
- WinError 10048 now reports **UDP 14550 is already in use** with direct guidance to close Mission Planner, another PC TeleRC instance, MAVProxy/QGroundControl, or another listener.
- WinError 10013 now reports **Windows denied access to UDP 14550** with guidance for excluded UDP ranges/security software.
- Diagnostics surfaces the targeted UDP failure directly in the Link row.
- Apply & Reconnect now waits for the old MAVLink worker to terminate, then waits briefly for Windows to release the UDP socket before rebinding.
- If the MAVLink worker cannot stop within the shutdown timeout, reconnect is aborted instead of starting a competing listener.

## Existing field-safety behavior retained
- Explicit ARM / DISARM.
- PC Control requires healthy MAVLink, fresh controller input and neutral throttle.
- Controller/MAVLink loss latches PC Control OFF.
- Selected controller GUID remains strict.
- Vehicle MAVLink system + component identity remains locked.
- Multi-attempt neutral/release sequence remains active.
- ArduRover GCS/telemetry fail-safe remains mandatory.

## Installation
Use **PC-TeleRC-Setup-v0.1.0a7.exe** for normal installation. Existing settings under `%LOCALAPPDATA%\PC-TeleRC` are preserved across upgrade/uninstall.

## Bench validation
Before ground testing:
1. Close Mission Planner and other MAVLink listeners.
2. Start one PC TeleRC instance only.
3. Confirm Diagnostics Link has no FAIL state.
4. Connect ESP32-S3 Wi-Fi and verify heartbeat/RX traffic.
5. Calibrate/verify the PXN controller.
6. Keep throttle authority low and test Wi-Fi/controller loss with wheels clear of the ground.

This remains a prerelease until the full physical fail-safe matrix is recorded.
