# PC TeleRC v0.1.1rc1 — Radio Dropdown Test Candidate

Base: stable v0.1.0a10, commit `7b84b7882c4010c34f158304cc9c8c8cc4cba77b`.

## Behavior
- Connection dropdown: ESP32-S3 Wi-Fi; LilyGO T3S3 SX1262 LoRa USB; HGLRC T ONE 900 MHz ELRS USB MAVLink.
- Profile-specific fields and independent saved LoRa/ELRS COM ports.
- Existing a10 Wi-Fi and wheel behavior retained. No later UDP/controller code imported.
- Old link released/closed before opening the selected profile. Fresh heartbeat and manual control enable required after reconnect. Disconnect cancels pending reconnect.
- LoRa setup reads/provisions both paired boards locally; masked pairing key is not written to PC settings or diagnostic reports.
- LoRa requires an active SX1262 BASE and current TeleRC CRC-framed firmware. Motor control is DIRECT-only and CH1/CH2. Initial FAILSAFE permits centered/neutral commands only during bounded DIRECT acquisition; arming requires DIRECT.
- ELRS requires USB MAVLink firmware, 460800 baud, and a linked compatible receiver. 5 Hz overrides; RF capacity remains limited on older 900 MHz radios.

## Evidence
- Original stable baseline: 50 tests passed locally before changes.
- Candidate: 76 local tests passed. Checks cover the original suite plus USB framing, setup exchange validation, serial backpressure, board rejection/cleanup, independent port persistence, radio-switch ordering, pending reconnect cancellation, and USB removal tests.
- Windows CI runs dependency integrity, syntax, full tests, PyInstaller packaging, Inno Setup installer, and SHA-256 generation before creating this draft.

## Hardware checks still required
- ESP32-S3: compare connection and wheel response with the stable a10 on the same rover.
- LoRa: paired SX1262 boards, native BASE USB, DIRECT motor controller, neutral acquisition, ARM/DISARM, unplug/radio-loss stop timing.
- ELRS: verify the actual T ONE COM port emits MAVLink, firmware TX/RX support, selected RF rate, CH1/CH2 behavior, and measured disconnect/override timeout.
- Transmitter takeover, radio range, and real failsafe timing are not established by software tests. Existing unsigned Windows build limitation remains.

This candidate is a draft and does not replace stable v0.1.0a10 as Latest.
