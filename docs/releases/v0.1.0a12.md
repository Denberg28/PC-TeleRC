# PC TeleRC v0.1.0a12 — Link and Controller Recovery

Corrective Windows prerelease for a11 wheel glitches and TeleRC connection compatibility.

## Changes
- Fix the unsupported pygame-ce joystick call that caused recurring controller errors in a11.
- Accept generic/boat autopilot heartbeats and nonstandard components; keep the first vehicle identity and UDP endpoint locked.
- Register and refresh the ESP32 telemetry destination using TELERC_DISCOVER_V1 every second, from the same socket used to receive telemetry and send control.
- Disconnect sends neutral/release for owned overrides, retries TELERC_DISCONNECT_V1, then closes UDP. Reconnect starts a fresh session and never resumes control automatically.
- Fixed targets filter both source IP and port before parsing. Process one received message per worker loop so malformed traffic cannot starve watchdog checks.
- Reject ARM/PC Control when mapped channels exceed CH4: the current bridge requires CH5–8 ignored.
- Preserve the 25–100% sensitivity slider, calibration/settings, default CH1 steering/CH2 drive, neutral prerequisites and manual control enable.

## Connection setup
Connect Windows to the ESP32 AP. Use listen address 0.0.0.0 and UDP port 14550; set ESP32 target IP 192.168.4.1 and target port 14550 for the standard bridge. Allow PC TeleRC through Windows Firewall on that network. Close competing UDP listeners and Android TeleRC before connecting. An existing bridge client lease may take five seconds to expire.

Click Apply & Reconnect, wait for a fresh heartbeat, check neutral pedals, then manually enable PC Control. Disconnect does not disarm.

## Validation and limits
The local suite passes 88 tests, including actual UDP pairing, repeated connect/disconnect, malformed traffic, stale heartbeat/recovery, control/release and exclusive port reuse. Windows release CI repeats tests, dependency checks, syntax compilation and executable/installer packaging.

This is an unsigned prerelease, not a hardware-validated reliability certification. Physical PXN input, ESP32 firmware compatibility, stop timing and RC transmitter takeover still require a wheels-lifted bench check. Discovery/disconnect support depends on the TeleRC bridge firmware. The current bridge filters GCS heartbeat rather than forwarding it; verify the rover's actual failsafe behavior instead of assuming PC GCS heartbeat reaches ArduRover. MAVLink control is unsigned and unencrypted; endpoint filtering is not authentication.

Review: docs/reviews/a12-link-reliability.md. No ESP32, Android or flight-controller parameters were changed.
