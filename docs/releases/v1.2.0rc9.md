# PC TeleRC v1.2.0rc9 — Route recovery and BASE reliability

Application-only reliability candidate based on published v1.2.0rc8. The compact
dark fleet UI, rover/radio icon and all existing mission controls are retained.

## Saved-route protection

If a saved draft is malformed, uses an unsupported version, has invalid encoding
or exceeds the size limit, opening and closing the application now preserves
the original file unchanged. It no longer replaces that file with an empty draft.

After you edit or import a replacement, the first save copies the original bytes
beside the draft as `rover-NNN.recovery-<unique-id>.json` before replacing it.
The log shows the recovery filename. A failed recovery copy blocks replacement;
the original stays intact. Recovery files are local route data: keep them private.
This preserves evidence for manual recovery; it does not repair damaged content
or make an unsupported future-version route executable.

The earlier standalone mission window also refuses to switch rover IDs when the
current draft cannot be saved. Export the route and resolve the storage failure
before switching. In the fleet window, each rover already has a separate editor.

## BASE connection state

When opening BASE succeeds but saving its USB-port preference fails, the UI now
correctly shows Close BASE, locks port editing and reports the preference error.
The same USB owner remains explicitly closable. Saving a display preference
never connects a rover, arms, starts or replays a command.

## Install and compatibility

Use PC-TeleRC-Setup-v1.2.0rc9.exe or extract the portable ZIP and run PC-TeleRC.exe.
Installer identity, settings location and draft schema are unchanged. Fleet
firmware remains 0.5.0rc1 and the PWM converter remains 1.0.5. Existing correctly
paired firmware needs no reflash. Private pairing keys/configurations/binaries
remain excluded; public radio images are RF-OFF.

The firmware ZIP is the unchanged hash-pinned rc7 archive with its original eleven
board-build records. Current Windows regressions, four additional frozen recovery
checks, native sanitizer/graph checks, source sanitation and downloaded asset/hash
verification gate publication. Exact results ship in test-evidence.zip. The UI
preview is reused from rc8 because this update changes failure recovery behavior.

This remains a **prerelease**, with an unsigned Windows application. Physical RF,
motor stopping, RC takeover, auxiliary OFF, fleet capacity and manual installed/
display-scaling acceptance remain pending. Command authorization, full upload
readback, normal Arm, one-shot Start, HOLD and loss policies are preserved.

Retain rc8 for application rollback; rc6 remains the designated mission-planning
baseline. Recovery copies are ignored by older versions and should be kept.
