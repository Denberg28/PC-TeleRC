# PC TeleRC v0.1.3rc1 — LoRa setup and USB connection candidate

The previous password field silently limited input to eight characters, so the nine-character `telerc123` preset could not be entered correctly. This candidate accepts 8–32 visible ASCII characters, preserves existing eight-character key derivation and rejects overlong password/hex-key input instead of accepting a truncated credential.

USB setup and the driving worker now distinguish access denied/busy, missing ports and unavailable devices without echoing raw driver exception buffers. A failed setup-port close keeps ownership, blocks another connection attempt and cancels previously queued reconnect callbacks. Reopening setup uses the current selected BASE port. Blank pairing clears stale frequency text and explains the required next step; compiled-password presets are identified as needing no provisioning.

The camera desktop, GPS map, keyboard/wheel controls and existing Wi-Fi/LoRa/ELRS wire protocols remain in place. Neutral acquisition, explicit ARM/control enable, manual recovery and watchdog timings are preserved. No firmware is changed or flashed by this application update. Existing paired firmware and the separately supplied pnp915-1 sketches remain compatible.

Validation: application regression suite, USB fault injection and password vectors, followed by Windows executable packaging, package/media verification and frozen camera/UI self-test. Release artifacts include the Windows installer, portable ZIP, source and SHA-256 checksums. This is a draft candidate; v0.1.2 stays stable. Physical COM9 access and RF operation require testing on the user's boards.
