# PC TeleRC v0.1.1rc5 — LilyGO SX1262 ArduRover direct pair

The existing LoRa profile accepted only the TeleRC direct motor controller heartbeat, so it could not drive the user's SpeedyBee ArduRover through a LilyGO pair. This candidate adds BASE/native-USB and ROVER/FC-UART sketches plus an explicitly advertised ARDUROVER backend. Real FC heartbeat, MANUAL mode and fresh authenticated rover status are required; startup neutral acquisition precedes motion. Radio-side stops/restarts now latch PC Control OFF and appear in the diagnostic report.

The candidate includes the delivered rc3/rc4 wheel-input and dropout fixes, Wi-Fi bridge 0.1.4, PWM converter 1.0.4, saved parameter evidence and the conditional motor-side patch. Existing Wi-Fi, direct-motor LoRa and ELRS profiles retain their protocols. New SX1262 firmware is 0.2.0 and requires both boards flashed; it does not speak Meshtastic or the older mesh protocol. The prior mesh work is retained separately under bridge/TeleRCMesh.

Downloads: Windows portable ZIP, Windows installer, LilyGO sketches and target builds, complete source checkpoint and SHA-256 manifests. Read docs/LILYGO-SX1262-ARDUROVER.md for GPIO43/44 wiring, per-board USB pairing, exact board selection and acceptance tests. Both radios start inactive until provisioned. No FC parameters are applied automatically; transmitter takeover remains RC6-controlled.

Validation: 122 local Python tests; both actual LoRa sketch roles compiled/executed with host mocks and ASan/UBSan, including 2,000 rapid combined-input cycles per role. The nine rc4 bridge/converter host configurations also pass. Release CI repeats Python tests on Windows, builds the executable/installer and compiles both sketches with ESP32 core 3.3.2 / RadioLib 7.2.1. CI results are recorded with this commit; target compilation is distinct from physical hardware validation.

Actual T3-S3 RF latency/range, Windows PXN hardware, UART/power behavior, stop timing and transmitter takeover remain to be measured. The candidate is unsigned and does not claim that LoRa fixes the ground/bump interruption. No automatic ARM or motion recovery is added; stable v0.1.0a10 remains the existing stable baseline.
