# PC TeleRC 0.1.5rc3 — mission release packaging

Pairs with the unchanged **TeleRC LoRa Mission 0.2.0rc1** BASE, ROVER, NODE 1 and NODE 2 sketch set.

This continuation strengthens release verification. The local Windows command and CI use the same builder. Packaging requires a newly generated frozen report from the current app version, with all 23 UI/media and authority checks true. A process exit code alone is insufficient. Only files matching the public firmware hash manifest are copied; extra private profiles or modified sketches stop the build. Source packaging rejects provisioned mission headers outside the standard sketch folders too.

CI preserves the verified portable package and build diagnostics before attempting the installer. A later installer failure therefore leaves the portable artifact available from its successful artifact-upload step. Workflow dispatch is also enabled for future rebuilds. This does not remove the hosted runner availability requirement.

AUTO monitoring now reports RC/FC takeover when the FC leaves AUTO, including sessions connected to a mission already in progress. Connection, upload, explicit RC arming, readback and one-shot START remain separate actions. No automatic reconnect, arm or mission resume is added.

Run `BUILD-WINDOWS-MISSION.cmd` with Python 3.12 on Windows. Generate private matching radio profiles outside the source tree with `firmware/mission/MAKE-MATCHING-SKETCHES.cmd`; flash all participating boards from one generation. See `docs/MISSION-PLANNING.md` for the operating workflow and `docs/evidence/mission-v0.1.5rc3/VALIDATION.md` for current qualification.

This remains a candidate. Physical RF, USB, power, RC takeover, stopping distance and independent accessory cutoff require the included hardware procedure. HOLD confirms an FC mode and does not guarantee physical stopping or auxiliary OFF.
