# PC TeleRC v0.1.0a11 — Sensitivity and Control Reliability

Windows prerelease with the TeleRC-style sensitivity slider and reviewed control/connection workflow.

## Changes
- Steering sensitivity slider: 25–100%, with percentage below the bar and saved settings.
- CH1 steering / CH2 drive; steering expo and throttle limit remain independent.
- Explicit Disconnect stops GCS heartbeats and closes UDP. Connect/Reconnect requires fresh heartbeat/input and manual control enable.
- Serialize control ticks and Disable/configuration transitions so drive commands cannot follow a completed release.
- Send commands to one accepted ArduRover UDP peer; surface local send failures to failsafe logic.
- Block ARM/control on pending network changes, invalid/stale frames, and overlapping controller axes.
- Detect controller reconnects and worker deadline misses; never auto-arm or auto-resume.
- DISARM disables overrides first. ARM/DISARM reports vehicle rejection, timeout, or heartbeat confirmation.
- Improve calibration validation, settings-save error handling, diagnostics lifetime, and the single-instance guard.

## Downloads
- **PC-TeleRC-Setup-v0.1.0a11.exe**: Windows x64 installer.
- **PC-TeleRC-portable-v0.1.0a11.zip**: extract the complete folder, then run PC-TeleRC.exe.
- SHA256-installer.txt and SHA256.txt: matching checksums.

Existing local settings and calibration are preserved. Existing custom channel mappings remain supported.

## Validation
The reviewed source passed 80 automated tests on Linux and Windows, syntax compilation, and dependency integrity checks. Release CI repeats those checks and builds the executable, portable ZIP, installer, and checksums.

## Field check
With the driven wheels lifted, verify wheel/pedal direction, CH1/CH2 output, sensitivity and throttle limit, transmitter takeover after Disable PC Control, and the rover's response to USB/Wi-Fi loss before ground operation.

Disable PC Control releases owned overrides but keeps telemetry connected. Disconnect also stops heartbeats and closes UDP; neither automatically disarms. Reconnect never resumes control automatically.

MAVLink 1 bridge compatibility is preserved; commands remain unsigned/unencrypted. Physical stop timing and transmitter handover still depend on the ESP32/ArduRover configuration and require bench validation. Use one active controller application at a time. The Windows installer is unsigned.
