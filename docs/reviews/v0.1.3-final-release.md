# PC TeleRC v0.1.3 final release review

## Scope

Reviewed the offline raster MBTiles reader, persistent map cache, lower-left map minimize/restore, frozen UI/media self-test, serial error descriptions, USB setup ownership, password validation, Windows packaging and direct 915 MHz preset provenance. The direct BASE/ROVER preset remains telerc123, 915000 kHz, zero relays. Existing working boards need no reflash for the desktop update.

The application and firmware source baseline is c02c2791e53c71825522231fe43e87137d5cd9e5. Application checks at that commit passed 207 tests, Windows packaging and the frozen UI/offline-tile/video self-test. Firmware host checks passed; exact preset targets were previously compiled by job 116320419322 and may be reused only after all firmware/preset sources and downloaded archive digests match.

## Finding and correction

The stable publication step rejected a stale draft target_commitish after newer successful builds. GitHub draft uploads had retained the earlier target metadata. The corrected publisher verifies a build-provenance manifest containing the current commit, workflow run and attempt, streams every required download to verify byte size and SHA256, checks both checksum manifests and all frozen UI checks, then sets the published release target to the tested commit. It refuses to move an existing mismatched tag or overwrite an already published stable release. Previous rollback releases are untouched.

Thirteen publication regression cases cover the stale draft, stale commit/run/attempt, altered installer bytes, inconsistent or incomplete manifests, missing downloads, failed frozen checks, existing tags, published releases and download failures. The Windows workflow runs these cases alongside the full application suite before packaging. Publication still depends on successful Windows and firmware jobs.

## Review limits

Raster PNG/JPEG/WebP MBTiles and previously cached tiles work offline; Android MapLibre/vector PBF databases are unsupported. No geographic map is bundled. Tile data is read-only with bounded decode sizes and SQL deadlines; map metadata does not create vehicle GPS or control input. USB errors avoid exposing raw driver buffers and credentials remain absent from persisted application settings.

The real direct LoRa link was confirmed by the user. RF range, long-duration operation, measured physical stop latency, electrical power integrity and named ELRS hardware still require hardware validation. This software release does not claim new hardware measurements or change watchdog thresholds.
